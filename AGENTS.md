# Model inventory documentation

When adding, upgrading, or removing models, refresh the **Deployed models and pricing** table in `README.md` as part of the change. Keep these tables directly below the Azure architecture diagram, replacing the old deployment screenshot.

- Open [Microsoft Foundry](https://ai.azure.com/) and select the appropriate resource/project through the UI. Navigate to **Operate → Assets → Models** (or **Models + endpoints** in the classic UI). Read every pagination page and reconcile the row count with the displayed total; do not assume the first page is complete. Enumerate every regional AI Services account in the resource group, not just the currently selected project. Reconcile the combined deployment list against the README and `terraform.tfvars`; a complete first account can still omit models deployed in another region. Capture deployment name, base model, exact deployed version, Global Standard or Data Zone Standard deployment type, and retirement date. Distinguish actual deployments from desired entries in `terraform.tfvars`; if live access is unavailable, say so rather than presenting configuration as a verified deployment.
- Keep README introductions to a compact date/units line and short ordering/units legend. Keep model pricing and catalog source links in this file, not in README tables. Do not add a Source column, reference-definition block, or pricing URL list to the README. Omit explanatory paragraphs before each group and do not add a pricing/lifecycle notes section. After the tables, use exactly: "These figures are approximate and may be incomplete; accuracy is not guaranteed."
- Keep three groups in this order: **Chat / multipurpose / code**, **Image generation**, and **Audio**. Within each group, use one table per model vendor, including vendors with a single entry. Do not separate models by SOTA status or country. Group by model developer (for example, DeepSeek or Moonshot AI), preserving native and Fireworks deployments as distinct rows. Order vendor tables by the approximate strength of their best listed model, strongest first, with OpenAI ahead of Anthropic as explicitly requested. Use only the models listed in that category to rank vendors. Within each table, order model rows by approximate strength, strongest first. Show each group’s total model count. Keep exactly one row per deployment; do not use continuation rows. Use only these columns: **Deployed model**, **Version**, **Retirement**, **Input**, and **Output**. Omit Focus, Type, Cached input, and Source columns. Use `—` for unavailable prices; avoid explanatory prose and footnote markers in cells. Preserve version strings exactly, normalize portal dates to `YYYY-MM-DD`, and update the verification date only when the inventory is rechecked. Preserve unavailable dates and far-future placeholders such as `2099-12-31`; never invent a retirement date.
- Review strength ordering when models change using current benchmark evidence and official model comparisons for the relevant task and version. Treat ordering as editorial, not a measured ranking of the Azure deployments. Do not infer strength from price, model size, release date, or “mini”/“Flash” alone. Keep equivalent native and Fireworks versions adjacent. For audio, order conversational models by overall capability, then append speech-to-text and text-to-speech specialists; their positions do not imply weaker performance at their own tasks.
- Research current **Azure** pricing independently using [Azure OpenAI pricing](https://azure.microsoft.com/en-us/pricing/details/azure-openai/), [Foundry model pricing](https://azure.microsoft.com/en-us/pricing/details/ai-foundry-models/), and the public [Azure Retail Prices API](https://learn.microsoft.com/en-us/rest/api/cost-management/retail-prices/azure-retail-prices). Static pricing pages may display `$-`; this is not a zero price. The API can be filtered by `serviceName eq 'Foundry Models'`, the model's product, `armRegionName`, and `priceType eq 'Consumption'`; request USD and follow every `NextPageLink`. Match the exact model/version, region, hosting provider, deployment type, and processing tier. Prefer model-specific official documentation to resolve abbreviated meter names.
- Keep native Azure and Fireworks deployments separate. Use actual Data Zone meters instead of applying an assumed percentage premium. For Claude, consult [Anthropic's Microsoft Foundry pricing rules](https://platform.claude.com/docs/en/about-claude/pricing#claude-in-microsoft-foundry-pricing) and the current model rate table. Do not silently substitute another provider's direct API pricing for Azure pricing.
- Include input and output prices where published, preserving short/long-context distinctions with compact pairs such as `$10/$20` (short or base price first, long price second), without repeated labels in cells. Put price component labels in the column headers (for example, **Input (Text/Image)**) and slash-separated values in cells (for example, `$5/$8`). Match values to the header order and use `—` for missing components. For OpenAI and Microsoft image-generation tables, use **Input (Text/Image)** and **Output**. Input pairs remain text/image and output contains only the image output price; omit text output prices and their placeholders. Never present these token rates as per-image prices. Convert to per-image costs only with a verified model-specific billed-token count for the stated dimensions and settings; do not assume that 1024×1024 pixels means 1,024 tokens. For audio, use **Input (Text/Audio/Image)** and **Output (Text/Audio)**; retain explicit hourly units for hourly charges. Keep billing-meter names and API implementation notes out of README price cells. For Black Forest Labs, retain the compact Input/Output headers; input is per megapixel and output pairs are first/additional megapixel prices. Keep `/MP` or `per MP` in those price cells so they cannot be mistaken for token prices; keep the interpretation of pairs here rather than expanding README headers. Do not use HTML line breaks or empty table cells. Keep short/long pairs on one line. Do not add cached-input or cache-write pricing to the tables. State currency, units, region, and pricing date. Convert per-1K token prices to per-1M by multiplying by 1,000. Keep hourly, image, audio, and megapixel charges explicitly labeled; do not mix them with text-token prices. If the portal flags fine-tuning, check inference and hosting meters. Preserve official source links below, and mark prices that cannot be verified explicitly rather than guessing.
- Use generic portal navigation and public documentation links. Never add subscription-specific or tenant-specific portal URLs, subscription/tenant IDs, private endpoints, credentials, or account-specific pricing offers to these instructions or the inventory table.
- For documentation-only updates, check the table count, ordering, duplicate names, units, source links, and `git diff --check`. Do not run `terraform apply` just to refresh documentation.
