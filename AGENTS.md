# Model inventory documentation

When adding, upgrading, or removing models, refresh the **Deployed models and pricing** table in `README.md` as part of the change. Keep these tables directly below the Azure architecture diagram, replacing the old deployment screenshot.

- Open [Microsoft Foundry](https://ai.azure.com/) and select the appropriate resource/project through the UI. Navigate to **Operate → Assets → Models** (or **Models + endpoints** in the classic UI). Read every pagination page and reconcile the row count with the displayed total; do not assume the first page is complete. Capture deployment name, base model, exact deployed version, Global Standard or Data Zone Standard deployment type, and retirement date. Distinguish actual deployments from desired entries in `terraform.tfvars`; if live access is unavailable, say so rather than presenting configuration as a verified deployment.
- Keep README introductions to a compact date/units line and short ordering/units legend. Keep source links inline in the tables using `[label](URL)`; do not add a reference-definition block or a separate URL list. Omit explanatory paragraphs before each group and do not add a pricing/lifecycle notes section. After the tables, use exactly: "These figures are approximate and may be incomplete; accuracy is not guaranteed."
- Keep three groups in this order: **Chat / multipurpose / code**, **Image generation**, and **Audio**. Within each group, use one table per model vendor, including vendors with a single entry. Do not separate models by SOTA status or country. Group by model developer (for example, DeepSeek or Moonshot AI), preserving native and Fireworks deployments as distinct rows. Order vendor tables by the approximate strength of their best listed model, strongest first, with OpenAI ahead of Anthropic as explicitly requested. Use only the models listed in that category to rank vendors. Within each table, order model rows by approximate strength, strongest first. Show each group’s total model count. Keep one row per deployment and a short **Focus** column. Display deployment types as **Global** and **Data Zone**. Use `—` for unavailable prices; avoid explanatory prose and footnote markers in cells. Preserve version strings exactly, normalize portal dates to `YYYY-MM-DD`, and update the verification date only when the inventory is rechecked. Preserve unavailable dates and far-future placeholders such as `2099-12-31`; never invent a retirement date.
- Review strength ordering when models change using current benchmark evidence and official model comparisons for the relevant task and version. Treat ordering as editorial, not a measured ranking of the Azure deployments. Do not infer strength from price, model size, release date, or “mini”/“Flash” alone. Keep equivalent native and Fireworks versions adjacent. For audio, order conversational models by overall capability, then append speech-to-text and text-to-speech specialists; their positions do not imply weaker performance at their own tasks.
- Research current **Azure** pricing independently using [Azure OpenAI pricing](https://azure.microsoft.com/en-us/pricing/details/azure-openai/), [Foundry model pricing](https://azure.microsoft.com/en-us/pricing/details/ai-foundry-models/), and the public [Azure Retail Prices API](https://learn.microsoft.com/en-us/rest/api/cost-management/retail-prices/azure-retail-prices). Static pricing pages may display `$-`; this is not a zero price. The API can be filtered by `serviceName eq 'Foundry Models'`, the model's product, `armRegionName`, and `priceType eq 'Consumption'`; request USD and follow every `NextPageLink`. Match the exact model/version, region, hosting provider, deployment type, and processing tier. Prefer model-specific official documentation to resolve abbreviated meter names.
- Keep native Azure and Fireworks deployments separate. Use actual Data Zone meters instead of applying an assumed percentage premium. For Claude, consult [Anthropic's Microsoft Foundry pricing rules](https://platform.claude.com/docs/en/about-claude/pricing#claude-in-microsoft-foundry-pricing) and the current model rate table. Do not silently substitute another provider's direct API pricing for Azure pricing.
- Include input, cached-input, and output prices where published, plus relevant cache-write and short/long-context distinctions. State currency, units, region, and pricing date. Convert per-1K token prices to per-1M by multiplying by 1,000. Keep hourly, image, audio, and megapixel charges explicitly labeled; do not mix them with text-token prices. If the portal flags fine-tuning, check inference and hosting meters. Link official sources, and mark prices that cannot be verified explicitly rather than guessing.
- Use generic portal navigation and public documentation links. Never add subscription-specific or tenant-specific portal URLs, subscription/tenant IDs, private endpoints, credentials, or account-specific pricing offers to these instructions or the inventory table.
- For documentation-only updates, check the table count, ordering, duplicate names, units, source links, and `git diff --check`. Do not run `terraform apply` just to refresh documentation.
